# 自适应偏好模型：最近加权 + 英文 / emoji 降级 + 整句让位

状态：设计稿，待用户确认。只在用户本机实现，暂不向上游提 PR。

## 为什么要做

用户日常打字时反复遇到三件事，都是同一个原因：输入法对「你选过什么」的记忆太粗，而且三处用到这份记忆的地方互不相通。

1. **`you` 打了很多次「又」，它始终排第五。** 候选是 `有 → you → 🤟 → 🫶 → 又`：「又」其实是汉字里的第二位，第 2–4 位被英文词 `you` 和它配的两个 emoji 占着。英文词固定插在第 2 位，学习只能把它提到第一，没有「从来不选就往后挪」；emoji 紧跟它对应的词，位置完全由配对关系决定。
2. **选了 emoji 没有任何效果。** 代码里选 emoji / 颜文字 / 符号明确「不记学习」；选英文词只记全局次数，不按输入串记。所以用户有意把它们选下来，下次位置也不变。
3. **`youshuo` 选了 4 次「又说」，第一位仍是 `有说 [句]`。** 整句候选直接插在最前面，不看用户的选择。
4. **「最近」没有分量。** 「同输入串下的选择次数」只是一个累加数，没有时间概念；用户最近连选 8 次「又」，对排序几乎没有影响。词的使用次数有 90 天半衰期的衰减，但那是另一套数据，管的不是这个。

参考：RIME 对每个用户词记 `commits`、`dee`、`tick` 三个数，`dee = 1 + 旧dee × e^(−Δtick/200)`，`tick` 是「这个用户词典又提交了一个词」的逻辑时钟（来源：`rime/librime` 的 `user_dictionary.cc`、`algo/dynamics.h`，由设计者读过源码）。

## 目标

- 用户连续几次选同一个词，它很快升上来。
- 用户从没选过的英文词 / emoji 不再占第 2–4 位。
- 用户选过的词不被整句候选压在后面。
- 选 emoji、颜文字、符号、英文词时也会被记住。

## 非目标

- 不做「随上文变化的偏好」。`吧 / 把` 这类仍靠现有的个人 n-gram 与竞争圈。（设计者的决定）
- 不动词频的 90 天衰减、模糊音、严格匹配、整句切分。
- 不解决 `shangou`、`yange` 这类用户**从没打过**的整句问题。整句只让给用户选过的词，这是用户的明确选择。
- 不向上游提 PR。

## 反目标（技术上做成了也算失败）

- 升级当天候选顺序突然变样。
- 用户正在学的英文词（比如第一次打的 `hello`）被藏起来。
- 打字变慢。仓库自己的目标是每键 10 ms 以内，当前长输入约 7 ms。
- 学习文件膨胀到影响加载。现有上限 `MAX_CHOICE_ENTRIES = 50_000`。

## 用户已经决定的

| 决定 | 内容 |
|---|---|
| 组织方式 | **统一的偏好模型**：学习器里加一层带时间衰减的偏好，词排序、英文 / emoji 位置、整句让位都读它。不是三个独立小改动。 |
| 衰减的时间 | **提交时钟**（RIME 式）：每记一次选择时钟走一格。不用日历时间，不用混合。 |
| 没选过的英文词 / emoji 去哪 | **排到前几个汉字候选后面**，仍在第一页，选一次就回到原位。 |

| 整句什么时候让位 | **只让给用户选过的词**（这个输入串下偏好大于 0 的词）。 |
| 总开关 | 加配置项 `[general] adaptive_learning`，**缺省开**，设置程序里也有开关。 |
| 范围 | 先在用户本机实现，需要时再提 PR。 |

## 设计者的决定（用户没问过，请复核）

- 衰减时间常数取 **200 次提交**（半衰期约 139 次）。依据：补测回放里半衰期 70–139 对 `you→又` 有效（没命中 40 → 28–29），≥ 280 基本无效。
- 「前几个汉字」取 **3 个**。
- 词频那套 90 天衰减**保持不变**，两套并存。
- 偏好表的键是 `(输入串, 候选文本)`，英文词 / emoji / 汉字共用，不另加类型字段（文本互不冲突）。
- 旧数据迁移：旧记录读进来时 `dee = 0`、`count` 保持原值，所以升级当天排序等价于现状。
- 「该输入串上屏了多少次」**不**用 `count` 之和（里面混着 `<raw>` 原样上屏和读音键下的重复记录，且旧数据里没有英文 / emoji 的记录），改用每条记录上**新增的 `n` 字段**，见第 1、5 节。（评审后新增）
- 降级做成**所有候选插入完之后的一次统一重排**，不放在 `insert_english` / `insert_following` 里，见第 5 节。（评审后新增）
- 开关接线沿用严格匹配的先例：macOS、Linux Server、Windows Server 三处都接；设置程序只改新的 `apps/settings`，不动 macOS 旧偏好页和 Windows 旧设置面板。（评审后新增）
- 撤销选择时的处理，见第 9 节。（评审后新增）

## 现状（代码事实，位置以 `crates/` 为根）

- **学习器**：`qingjian-learning/src/frequency_learner/`。`choices: HashMap<输入串, HashMap<词, u32>>` 只存累加次数；`record_choice(input, reading, text)` 在每次选择时调用，`choice_weight(input, text)` 读取；超过 50 000 条时 `decay_choices()` 整体缩减。
- **选择记录文件**：`user-choices.tsv`，每行 `输入串\t词\t次数`，文件头是 `#` 注释行。`parse_counted_pair` 只取前三个字段、忽略多余的列，注释行被跳过。所以**追加列、追加头部注释，旧版本仍能读**。
- **什么时候记录**（`qingjian-core/src/engine/commit/mod.rs`）：汉字、形码、云端词调用 `record_choice`；**emoji、颜文字、符号不记录**（注释写「不记学习」）；英文候选只 `record`（全局次数）并 `note_english_commit`，**不按输入串记选择**；整句不记。
- **`Learner` trait**：`qingjian-core/src/engine/learning/learner.rs`，除 `record` / `weight` 外都有默认空实现。`MutedLearner`（`learning/muted.rs`）包一层，私密输入时静音。
- **排序**：`qingjian-core/src/ranking/mod.rs` 的 `rank()`，选择次数经 `contention_key()` 进入竞争圈（次数不少于同组最高者一半的词键相同，交给上下文得分），圈外按次数排。
- **英文词摆放**：`engine/extras.rs` 的 `insert_english()`，缺省 `position = 1`（第 2 位）；`insert_emoji()` → `insert_following()` 把 emoji 插在对应词（含英文词）后面。
- **整句插入**：`engine/query/converting.rs` 的 `insert_sentence()` / `plain_sentence()`，整句直接插在最前面（`leading_english` 之后）。已有 `behind_spelled` 机制可以把整句插到某个词后面。

## 设计

### 1. 偏好表

学习器里新增偏好表，键 `(输入串, 候选文本)`，值：

- `count: u32`：长期次数，不衰减，沿用现有 `choices` 的语义。
- `dee: f32`：短期权重。
- `tick: u64`：最后一次更新时的时钟。
- `n: u32`：**自新模型启用以来**的选择次数。旧数据读进来时 `n = 0`。它是「证据」的唯一来源（见第 5 节），所以升级当天没有任何输入串满足降级门槛。

学习器另有一个全局 `clock: u64`。

**记录**一次选择：`clock += 1`；`dee = 1 + dee × exp(−(clock − tick) / 200)`；`tick = clock`；`count += 1`；`n += 1`。`n` 只在**字面输入串键**下记，不在读音键（`generalizes` 时额外记的那份）下记，也不记 `<raw>`。
**读取**当前短期权重：`dee × exp(−(clock − tick) / 200)`。

现有 `choices` 与新表合并为同一份数据，不并存两份。

### 2. 记录点

所有「上屏时有输入串」的候选都记录：汉字、形码、云端词（已有），以及**新增**的英文词、emoji、颜文字、符号。整句不记。**原样上屏一个英文词**（回车，输入串等于该词）算作选中这个英文候选，记在 `(输入串, 该词)` 下，而不是 `<raw>`，这样正在学的英文词不会被当成「没选过」。私密输入时不记（`MutedLearner` 已静音）。

### 3. `Learner` trait 的新方法

全部给默认空实现，保证别的实现和测试桩不用改：

- 读短期权重：`(输入串, 文本) → f32`。
- 读该输入串累计上屏次数：`输入串 → u32`（该输入串下所有候选 `count` 之和）。
- 记录 emoji / 英文候选的选择（或让现有 `record_choice` 覆盖它们）。

`choice_weight()` 保持现状（返回 `count`），因为 `commit/mod.rs` 里的自动造词门槛、`extras.rs` 的英文仲裁都在用它。

### 4. 排序

`adaptive_learning` 开时，竞争圈用**有效偏好 = `count + β × 短期权重`** 代替单纯的 `count`。`β` 的起始值取 10，由回放调参定（设计者的猜测）。关时用 `count`，即现状。迁移后短期权重为 0，所以升级当天有效偏好 = `count`，行为与现状等价。

### 5. 英文词与 emoji 降级

在 `insert_english`、`insert_emoji`、`insert_sentence` 都跑完之后，加**一次统一重排**（`demote_unchosen_extras`）：

- **对象**：候选列表里 `English`、`Emoji`、`Kaomoji`、`Symbol` 四种。每个候选**各自**判断，挂在汉字词上的 emoji、挂在英文词上的 emoji 都一样。
- **证据**：该输入串的 `Σ n`（只对字面键的条目求和，不含 `<raw>`）≥ 5。
- **「没选过」**：这个候选的 `n == 0`；英文词另外要求全局 `weight(word) == 0`（旧数据里英文词只有全局次数，没有按输入串的记录，这一条保证旧数据里选过的英文词不被降级）。
- **落点**：满足以上条件的候选移到前 3 个「汉字候选」之后。「汉字候选」指 `Chinese`、`Sentence`、`Code`、`Cloud`。不足 3 个时放在最后一个汉字候选之后。被移动的候选保持彼此的相对顺序。
- **例外**：已经排在第 0 位的英文候选（拼音「不像话」时英文词排第一的既有规则）不降级。
- 选中它一次，`n` 变 1，下次不再满足条件，回到原位。
- 因为是在所有插入完成之后统一重排，`EMOJI_SCAN`（现为 5）不影响降级；`chinese_first` 开着时整句先进来，重排只数候选类型，不特殊处理。
- 「仍在第一页」是目标，不是硬约束：每页候选数可配置，页容量很小时落点可能在第二页，可以接受。

### 6. 整句让位

整句候选插入前，如果候选列表里有汉字词，其音节连写正好等于整段输入，**且**这个输入串下它的 `count > 0`（用户选过），整句插到它后面，不再置顶。复用现有的 `behind_spelled` 位置逻辑。其余情况不变。

### 7. 配置与接线

- 配置项 `[general] adaptive_learning`，缺省 `true`，写进配置模板的注释。
- `Engine` 加 `set_adaptive_learning(bool)`；开关关掉时第 4–6 节全部退回现状，第 1–2 节的记录照常进行（保证重新打开时有数据）。
- 接线位置：macOS 宿主读配置处、Linux Server 与 Windows Server 的启动与热重载各一处（共 4 处），沿用严格匹配的做法；另加命令行参数 `--adaptive` 便于回放对比。
- 设置程序只改新的 `apps/settings`「候选」页加一个开关；macOS 旧偏好页（`apps/macos/src/preferences`）和 Windows 旧设置面板不动。
- 开关缺省开，所以三个平台的行为都会变；本次只在用户的 macOS 上验证，其余平台的接线只保证能编译。

### 8. 持久化

仍写 `user-choices.tsv`：每行 `输入串\t词\t次数\tdee\ttick\tn`，文件头加一行注释记录全局时钟。旧版本读新文件只会用前三列，**可以回退**。老文件没有后三列时，`dee = 0`、`tick = 当前时钟`、`n = 0`。条目数超过 50 000 时的缩减逻辑沿用，缩减时可优先丢 `count` 小且 `dee` 接近 0 的条目。

### 9. 撤销选择

用户上屏后立刻退格撤销（`unrecord_choice`）：`count` 与 `n` 各减 1，`dee` 近似回退为 `max(0, dee − 1)`，**时钟不回拨**，不要求精确还原。英文词、emoji 现在没有对应的撤销记录，实现时要把它们纳入 `LastCommit` 的选择记录，细节由实现者决定。

## 测试与验收

1. **单元测试**：衰减公式；5 次门槛（4 次不降、5 次且没选过才降）；选过一次回到原位；整句让位（选过才让，没选过不让）；老文件读入后排序等于现状；开关关闭时与现状一致。
2. **冷启动回放**（`--replay`，不带 `--user-dict`）：词首选命中**不低于现在**（基线约 89.5%）。这里的「没命中」指回放报告里的**首选没命中**（选中的词不在第一位），不是「不在候选里」。`you→又` 首选没命中从 40 降到约 28 以下；`youshuo→又说` 在日志里的来源是 `word`（4 次），与 `有说`（`sentence`，2 次）并存，验收是它不再被 `有说` 压在第一位之后。
3. **性质回归**：`ba` 在好 / 走 / 行 后出「吧」、没有 / 我们 / 帮我 后出「把」；`bi` 笔 16 / 币 13 / 比 10 时「比」第一；冷引擎 `shi` 选一次就升到第 1。
4. **性能**：长输入每键总耗时不超过 10 ms。
5. 用户本机试用后确认。

## 风险

- 记录 emoji / 英文会增加 `user-choices.tsv` 的条目数。
- 英文降级的判断依赖「该输入串累计上屏次数」，对很少打的输入串不会触发，这是有意的。
- 圈内的软权重（`β`）需要用回放调，起始值只是猜测。
- 英文词摆放里还有「拼音不像话时英文词排第一」的既有逻辑，降级规则不应影响它（第 5 节的例外）。
- 回放日志里的旧记录没有英文 / emoji 的按输入串选择，所以回放能验证的是汉字词的最近加权和整句让位；英文 / emoji 降级主要靠单元测试和用户试用验证。
